Spatial & Geofencing

MongoDB natively supports 2dsphere geometric indexes with operators like $geoWithin, $geoNear, $geoIntersects for point-in-polygon, proximity, and corridor checks — and all analytical processing (route deviation, stop detection, sequence-aware skip logic) is handled at the aggregation pipeline level using $setWindowFields, $shift, and sliding window functions, eliminating the need for any external geospatial engine.
RequirementApproach
~800 PIP checks/sec2dsphere + $geoWithin — sub-ms per check; trivial for single node.
Route corridor deviation (100m)Distance calc against route LineString per ping, configurable threshold.
Stop arrival/departure/skip detectionSequence-aware aggregation with $setWindowFields.
Nearest bus stop (passenger app)$geoNear returns sorted-by-distance results in < 5ms.

Operational Monitoring

MongoDB Change Streams, Atlas Triggers, and Atlas Stream Processing provide sub-second event propagation for live tracking, ETA recalculation, and alert triggering — while all detection logic (overspeed, harsh braking/acceleration, unauthorized stops, breakdown inference, schedule deviation, panic lifecycle) is evaluated using aggregation pipelines with $setWindowFields, $shift, $dateDiff, and sliding window expressions directly at the database layer. Atlas Triggers enable serverless reactions without app code, and Stream Processing supports continuous windowed analytics — eliminating external CEP or Kafka Streams.
RequirementApproach
Live tracking < 5s freshnessCurrent-state collection updated per ping via Change Stream.
ETA cascade per GPS pingRecomputed on each event; downstream stops updated atomically.
Schedule adherence (5/10 min)$dateDiff against schedule master; configurable thresholds.
Unauthorized stop (> 3 min)Sliding window counting stationary pings outside stop radius.
Breakdown inferenceBehaviour pattern (prolonged zero-speed) + device-reported events.
Overspeed / Harsh events$shift + speed delta computation between consecutive pings.
Panic button lifecycleActive until manual close; Change Stream triggers CCS/Police notification.

4. Feature Implementation Details

4.1 Live Dashboard

PoC: Express API serves vehicle positions from vehicle_current_state. Leaflet.js renders markers with color-coded status (running/idle/stopped). Polling every 3s.

Production: WebSocket/SSE push via Change Streams for true real-time. Read from secondaries for dashboard traffic. CDN for static assets.

4.2 Route Playback

PoC: Query gps_events Time Series by vehicleId + time range. Client-side animation with play/pause/speed controls. Trail color-coded by speed.

Production: Pre-aggregated trip summaries for fast initial load. Streaming cursor for very long trips. Playback at 1x/2x/4x/10x.

4.3 Alert System

PoC: Change Stream on vehicle_current_state evaluates rules (overspeed > 60 km/h, geofence breach, etc.) and inserts alerts. GPS context trail (±2 min) shown with speed graph and calculation formula.

Production: Atlas Triggers for serverless processing. Push notifications to CCS/Police for panic. Alert escalation chains with SLA timers.

4.4 Geofencing

PoC: GeoJSON polygons stored in geofences collection. $geoWithin checks on each GPS update. Route deviation via distance-to-LineString calculation.

Production: Dynamic geofence CRUD with versioning. Zone-specific speed limits. Entry/exit event logging. ~800 checks/sec per node.

4.5 Reports (9 in PoC, 16 target)

PoC: Each report is a MongoDB aggregation pipeline. "Show Logic" button reveals the exact pipeline stages, operators, and detection algorithms used. Bus filter for per-vehicle vs cumulative comparison.

Production: Materialized views for frequently-accessed reports. Scheduled report generation. Export to Excel/PDF/Word. Division and depot-level drill-down.

4.6 GPS Data Ingest

PoC: Seed button generates historical data (configurable 2h–48h). Live simulator produces 50 events every 10 seconds with realistic movement along routes.

Production: Kafka/Event Hub as durable ingest buffer (prevents data loss at 80K msg/sec). Batch writes with ordered:false for maximum throughput. Idempotent writes to handle device retries.

4.7 ETA/Schedule Adherence

PoC: Schedule adherence report compares actual arrival timestamps against scheduled times using $dateDiff.

Production: ETA recalculated per GPS ping using current speed + remaining route geometry. Cascaded to all downstream stops. Warning at 5 min deviation, critical at 10 min.

5. Production Enhancements

5.1 Apache Kafka / Event Hub Integration

AspectBefore (PoC)After (Production)
IngestDirect HTTP → MongoDBDevice → Kafka → Consumer → MongoDB
DurabilityLost if server downKafka retains until consumed
Throughput~1K msg/sec80K+ msg/sec sustained
Back-pressureNoneKafka absorbs spikes

5.2 Atlas Triggers

Replace in-process Change Stream with managed serverless functions. Benefits: auto-scaling, no server maintenance, built-in retry, event-driven notifications without application deployment.

5.3 Atlas Stream Processing

Continuous windowed analytics using native MQL on the ingest stream:

  • Tumbling windows: 1-minute aggregates (avg speed, distance per vehicle)
  • Sliding windows: Detect sustained overspeed or prolonged stops in real-time
  • Output: Materialized to collections for instant dashboard reads

5.4 Online Archive

Auto-tier GPS data older than 90 days to low-cost archival storage. Data remains queryable via the same connection string. Cost reduction: up to 99% for cold data.

5.5 Data Federation

Query across hot cluster + Online Archive + S3 with a single MQL query. Enables yearly reports spanning hot and archived data without ETL pipelines.

5.6 Atlas Search (Future)

Full-text search across vehicle IDs, route names, alert descriptions for operational search UIs.

Getting Started (Step by Step)

  1. Open the Live Dashboard — Navigate to the app URL
  2. If no vehicles visible: Select a duration from the hours dropdown (2h, 6h, 12h, 24h) and click 🌱 Seed Data to populate historical GPS records and alerts
  3. Start live movement: Click ▶ Simulator — buses begin moving in real-time on the map (50 GPS events every 10 seconds)
  4. Explore Playback: Select a vehicle and time range to replay its historical journey with speed controls
  5. View Alerts: Click any alert to see GPS trail context, speed graph, and detection formula
  6. Run Reports: Click any report card, then click table rows to see GPS trail + detection logic on map
  7. Review Architecture: 8 tabs covering schema, APIs, features, sizing, compliance
  8. Stop Simulator: Click ⏹ Simulator when done
Approximate data per seed duration:
