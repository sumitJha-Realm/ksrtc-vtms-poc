🗺️ Live Dashboard / (Home)

Real-time view of all 50 vehicles on a map, with status indicators, speed, and route information.

  1. View all vehicles: Open the app at http://localhost:3000 — all buses appear on the map as colored markers (green = running, orange = idle, red = stopped)
  2. Click a vehicle marker: A popup shows vehicle ID, current speed, route, depot, heading, and last update time
  3. Side panel stats: The left panel shows fleet-wide statistics — total vehicles, running/idle/stopped counts, alerts count
  4. Auto-refresh: The dashboard polls every 5 seconds for new positions. Vehicles move smoothly on the map as the GPS simulator generates new data
  5. Speed-based colors: Marker colors change based on speed — watch for red (stopped), orange (slow/idle), green (normal), and pulsing red (overspeed)
💡 MongoDB Feature: The dashboard queries vehicle_current_state collection — a standard collection updated in real-time by Change Streams. Each document represents the LATEST state of one vehicle (single-document update pattern).
Change Streams vehicle_current_state Geospatial Queries

▶️ Route Playback /playback

Replay any vehicle's historical journey — see the bus move along its route with speed changes, direction, and timestamps.

  1. Select a vehicle: Use the dropdown at the top to choose a bus (e.g., KA-19-F-1001)
  2. Pick a time range: Choose "Last 1 Hour", "Last 6 Hours", or set custom from/to dates
  3. Click "Load Trip": The GPS trail loads on the map — a colored polyline showing the path
  4. Watch playback: The bus marker moves along the trail automatically. Speed is shown in the panel. The bus icon rotates to match heading/direction
  5. Use playback controls: Pause/Play, speed up (2×, 4×, 8×), or drag the progress slider to jump to any point in time
  6. Speed coloring: The trail line changes color — green (normal), orange (elevated), red (overspeeding) — so you can see where violations happened
💡 MongoDB Feature: Playback queries the gps_events Time Series collection with $match on vehicleId + time range. The Time Series bucket optimization makes this extremely fast even with millions of documents — only relevant time buckets are scanned.
Time Series Collection Bucket Optimization $sort by timestamp Geospatial

🚨 Alerts /alerts-page

View all real-time alerts with GPS trail context — see exactly how each alert was triggered on the map.

  1. Browse alerts: The left panel shows all alerts sorted by time. Each has a severity dot (red = critical, orange = warning), type, vehicle ID, and timestamp
  2. Click any alert: The right panel lights up with:
    • 🗺️ Map: GPS trail ±2 minutes around the alert, color-coded by speed
    • 📍 Alert point: Pulsing red marker showing exactly where it was triggered
    • 📊 Speed graph: Bar chart showing speed over the ±2 min window
    • 🧮 Calculation box: The exact formula used to detect this alert
  3. Read the explanation: Below the map, a human-readable sentence explains what happened (e.g., "Bus was traveling at 55 km/h and accelerated to 92 km/h, exceeding the 60 km/h limit")
  4. Acknowledge alerts: Use the ACK/Close buttons to update alert status
  5. Filter by type: Use the dropdown filters to show only overspeed, harsh braking, geofence violations, etc.
💡 MongoDB Features: Alerts are generated by a Change Stream on vehicle_current_state. The GPS context uses $setWindowFields with $shift to compute speed deltas around the alert timestamp. The trail query leverages Time Series bucket pruning for fast ±2 min lookups.
Change Streams $setWindowFields $shift Time Series Geofencing

📋 Reports /reports

Generate analytical reports using MongoDB aggregation pipelines. Each report shows a "Show Logic" button explaining the detection algorithm.

  1. Select a report type: Click any report card to generate it:
    • 📊 Vehicle Tracking Summary — distance, hours, speed per vehicle
    • ⚡ Overspeeding Violations — all overspeed events
    • 🛑 Harsh Braking/Acceleration — window function detection
    • 🚫 Unauthorized Stops — sliding window stop detection
    • 📅 Schedule Adherence — actual vs expected timing
    • 🔧 Breakdown Incidents
    • 🏢 Depot Status — fleet distribution
    • ⏭ Stop Skipping — missed bus stops
    • 🆘 Panic/SOS Events
  2. Click "⚙ Show Logic": On any report card, click the button in the top-right corner to see:
    • Which MongoDB collection is queried
    • MongoDB features used ($setWindowFields, $group, etc.)
    • Step-by-step processing logic
    • The actual aggregation pipeline code
  3. View results: The table shows on the left side with all matching records
  4. Click a table row: For events with GPS data (harsh braking, overspeed, unauthorized stops), clicking a row shows:
    • 🗺️ GPS trail on the map (right panel) — color-coded by speed
    • 📊 Speed graph showing the event in context
    • 🧮 Calculation formula (e.g., acceleration = (Δspeed / 3.6) / Δtime)
💡 MongoDB Features: Reports heavily use $setWindowFields for computing acceleration (harsh events) and detecting stationary periods (unauthorized stops). The $shift operator looks at previous GPS pings, and $sum with window: { documents: [-17, 0] } creates sliding windows over 3-minute periods.
$setWindowFields $shift Sliding Window $dateTrunc $group $lookup

🖥️ Running the Application Locally

  1. Start the server: cd ksrtc-vtms-poc && node server.js — starts Express on port 3000, connects to MongoDB Atlas, starts Change Stream processor
  2. Open browser: Navigate to http://localhost:3000
  3. If Live Dashboard records are not visible: Choose a duration from the hours dropdown and click 🌱 Seed Data to load historical records, then click ▶ Simulator to start live movement updates.
  4. Seed historical data (recommended first): On the Live Dashboard, select a duration from the hours dropdown (2h, 4h, 6h, 12h, 24h, 36h, 48h) and click 🌱 Seed Data. Confirm the prompt after reviewing estimated GPS events and alerts. This creates historical records for Reports, Alerts, and Playback. Data is appended — nothing is deleted.
  5. Run live simulator: Click ▶ Simulator to start continuous live GPS generation (50 events every 10 seconds). You should see buses move in real-time on the map. Click again (⏹ Simulator) to stop.
  6. Validate simulator state: Check the simulator button label/state on the dashboard and verify the map timestamp updates while buses move.
  7. Explore pages: Use the navigation bar to switch between Dashboard, Playback, Alerts, Reports, Architecture, Enhancements, and this Guide
💡 Tip: Click "🌱 Seed Data" first to populate historical data for Reports, Alerts, and Playback pages. Then click "▶ Simulator" for live bus movement on the Dashboard. Both actions are UI buttons — no terminal commands needed.
📊 Approximate events per duration:
2h → ~36K GPS events, 6 alerts  |  6h → ~108K events, 18 alerts  |  12h → ~216K events, 36 alerts  |  24h → ~432K events, 72 alerts
