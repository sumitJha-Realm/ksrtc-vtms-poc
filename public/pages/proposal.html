1. Executive Summary

This document presents how MongoDB Atlas addresses all KPI and SLA requirements for the KSRTC Vehicle Tracking & Management System — covering 8,000+ vehicles, 86 depots, real-time telemetry at 70M GPS records/day, and 16 operational report types.

A working Proof of Concept demonstrates core patterns including Time Series ingestion, Change Stream alerting, geospatial queries, and aggregation-based analytics — all running on a single MongoDB Atlas platform.

Key Reference: Toyota Connected operates 9M+ connected devices on MongoDB Atlas — validating this architecture at far greater scale than KSRTC's requirements. View Case Study →

3. How to Use the Demo

  1. Open the app: Visit https://ksrtc-vtms-poc.vercel.app

  3. Start live simulation: Click ▶ Simulator on the dashboard. Buses move in real-time on the map.
  4. Explore features:
    • Live Dashboard — Real-time positions, depot/status filters, route tracks, bus stops
    • Route Playback — Select bus + time range → animated GPS trail replay
    • Alerts — Click any alert → see GPS trail, speed graph, detection formula
    • Reports — Click report card → results + "⚙ Show Logic" for pipeline details
    • Architecture — Current vs proposed architecture, schemas, indexes, sizing
    • Enhancements — Production roadmap with Kafka, Triggers, Stream Processing
  5. Stop simulator: Click ⏹ Simulator when done.
Tip: Seed data first (creates history for Reports, Alerts, Playback), then start Simulator for live movement.

5.4 Spatial & Geofencing

MongoDB natively supports 2dsphere geometric indexes with operators ($geoWithin, $geoNear, $geoIntersects) for point-in-polygon, proximity, and corridor checks. All analytical processing — route deviation, stop detection, sequence-aware skip logic — is handled at the aggregation pipeline level using $setWindowFields, $shift, and sliding window functions, eliminating any external geospatial engine.

RequirementSolution
~800 PIP checks/sec$geoWithin + 2dsphere = sub-ms/check. 800/sec trivial for single node.
Route corridor deviation (100m)Distance vs route LineString per ping, configurable threshold.
Stop arrival/departure/skipSequence-aware aggregation with $setWindowFields.
Nearest stop (mobile app)$geoNear sorted by distance, < 5ms response.

5.5 Operational Monitoring

MongoDB Change Streams, Atlas Triggers, and Atlas Stream Processing provide sub-second event propagation for live tracking, ETA recalculation, and alert triggering. All detection logic is evaluated using aggregation pipelines with $setWindowFields, $shift, $dateDiff, and sliding window expressions at the database layer. Atlas Triggers enable serverless reactions (notifications, escalations), and Stream Processing supports continuous windowed analytics — eliminating external CEP or Kafka Streams.

RequirementSolution
Live tracking < 5s freshnessChange Stream → current-state collection; 3s dashboard poll.
ETA/ETD per ping, cascadedRecomputed per GPS event; downstream stops updated atomically.
Schedule adherence (5/10 min)$dateDiff vs schedule; configurable thresholds.
Unauthorized stop (> 3 min)Sliding window on stationary pings outside stop radius.
Overspeed / Harsh events$setWindowFields + $shift computes delta between pings.
Breakdown inferenceBehaviour pattern detection + device-reported ingest.
Panic button lifecycleActive until manual close; triggers push to CCS + Police.

8. Production Enhancement Roadmap

8.1 Apache Kafka — Ingest Buffer

Why: Decouples device ingest from database writes. Handles burst traffic (1K+ msg/sec peaks), provides replay capability, and prevents data loss during maintenance.

Result: Zero data loss guarantee at 80K+ messages/sec capacity.

8.2 Atlas Triggers — Serverless Event Processing

Why: Replace in-process Change Stream watchers with managed serverless functions. Auto-scales with event volume, no infrastructure to manage.

Result: Alert notifications, escalations, and integrations triggered automatically without application deployment.

8.3 Atlas Stream Processing — Continuous Windowed Analytics

Why: Run tumbling and sliding window computations on the live GPS stream in native MQL. Detect patterns (unauthorized stops, speed anomalies) continuously without batch queries.

Result: Real-time derived metrics and KPIs with millisecond latency.

8.4 Online Archive — Cost-Optimized Retention

Why: Auto-tier GPS data older than 90 days to low-cost cloud storage while keeping it fully queryable via standard MongoDB queries.

Result: 99% storage cost reduction on historical data with zero query code changes.

8.5 Data Federation — Cross-Tier Queries

Why: Query across hot cluster + Online Archive + S3 with a single MQL query. Enables yearly reports and long-term trend analysis.

Result: Unified query interface across all data tiers; no ETL pipelines needed.
